01

团队协作，不再靠网盘接力

大文件继续放网盘，进度、交付物和交接都在工作台里。

以前
录制传网盘 → 制作人下载粗剪再传 → 精剪下载精剪再传 → 制作人写 Show notes → 运营分发。每一步都要在群里问，没人说得清这一期卡在哪。
现在
上一步点“完成”，下一步的负责人在企业微信群里被 @，打开链接就能看到素材链接、要求和 AI 初稿。
  • 按步骤自动流转：每一步有负责人、必交项和状态
  • 企业微信群机器人：轮到谁就 @ 谁，退回时附上原因
  • 大文件不搬家：视频放百度网盘，工作台只存链接和压缩音频
  • 香港 / 新加坡部署：国内外伙伴都能打开，不需要备案
  • 账号和角色：录制团队、制作人、精剪伙伴、文案伙伴、运营伙伴
02

AI 先做，人审核

AI 负责出初稿，人只做判断。

✂️

AI 粗剪方案

根据逐字转写给出剪点方案，标注每一处删除的原文、上下文和理由。审核后一键生成剪映草稿。

📝

Show notes

根据定稿文字稿生成标题候选、简介、时间轴、专业概念、金句和关键词。

🎨

单集封面

按节目档案里的品牌风格出图，禁用元素一律不出现。

📣

全平台文案

为小宇宙、小红书、B 站等平台分别写好标题、正文、标签和发布检查项。

🔍

独立审查

每份 AI 初稿都由另一家厂商的模型按交付标准逐条检查，不让模型自己审自己。

📈

定稿复盘

对比 AI 稿和人工定稿，提出剪辑规则修改建议，制作人确认后写进规则库。

03

每一步，用最合适的模型

在设置页随时更换模型，不用改代码。

步骤执行模型审查模型为什么
转写SenseVoice—中文准，带逐字时间戳，服务器上免费运行
粗剪OpenAI CodexClaude结构化输出几百个剪点
精剪建议ClaudeOpenAI Codex细判断取舍；和粗剪换厂商，互相检查
Show notesClaudeGPT中文长文本的概括和归纳
封面GPT 生图Claude图像生成，审查模型直接看图

每一步开工前，下游的模型先按上游的交付标准检查一遍上游产出，发现问题就退回。

04

剪辑规则，从人工定稿里学

规则来自多期节目「AI 第一稿 vs 人工定稿」的逐条对比，适用于所有知识类播客。

观点和案例必须保留

表达可以精简，但不能因为说得乱就整段删。取舍以句子为单位。

同一个点只讲一遍

第二种说法、第二个类比、讲完之后的总结回指都删。

推测和假设要删

即使带观点也删；事实、定性和结论保留。

60–70%粗剪占原始时长
55–65%精剪定稿
≈50%音频平台版
6 秒/分钟逐字精简的覆盖率
05

适用于任何知识类播客

在节目档案里填写你的领域，AI 就按你的标准工作。

⚖️

法律对谈

法条和数字必须和录音一致；涉及具体案件用“据报道”，不对未判决的案件下结论。

🏛️

历史讲述

年份和人名必须准确；区分史料记载和讲述者的推测。

🔬

科普访谈

研究结论保留限定条件；不把单篇研究说成定论。

06

开始使用

先在自己电脑上试用，满意后再部署到服务器。

本地试用（不调用模型，不花钱）

git clone https://github.com/rene-wang1024/podcast-assistant.git
cd podcast-assistant
pip install -r requirements.txt
PIPELINE_PROVIDER_OVERRIDE=mock \
  uvicorn app.main:app --port 8000

部署到香港服务器

curl -fsSL https://get.docker.com | sh
git clone https://github.com/rene-wang1024/podcast-assistant.git
cd podcast-assistant && cp .env.example .env
nano .env        # 填 SECRET_KEY 和 API Key
docker compose up -d --build
